# SDN-MFA-V2

[English](README.md) | [راهنمای اجرای آزمایش‌ها](docs/USAGE.fa.md)

SDN-MFA-V2 پیاده‌سازی پژوهشی من برای بررسی احراز هویت چندعاملی در شبکه نرم‌افزارمحور است. در این پروژه، احراز هویت و مجوزدهی شبکه ابتدا جدا از هم سنجیده می‌شوند و سپس در یک آزمایش زنجیره‌ای، مسیر کامل از تلاش برای ورود تا نتیجه عملیات شبکه بررسی می‌شود.

آزمایشگاه به‌طور کامل داخل Mininet اجرا می‌شود. کنترلر آن با Ryu و OpenFlow 1.3 نوشته شده، PostgreSQL برای ثبت شواهد و ادامه اجرای متوقف‌شده به کار می‌رود و گزارش‌ساز، خروجی فارسی پایان‌نامه و خروجی انگلیسی مناسب مقاله تولید می‌کند.

## چه چیزی اندازه‌گیری می‌شود؟

طرح آزمایش دو کنترل مستقل دارد:

- سیاست احراز هویت مشخص می‌کند قبل از ایجاد نشست چه عامل‌هایی باید تأیید شوند؛
- binding شبکه مشخص می‌کند پس از ورود، کدام ویژگی‌های مبدأ و محل اتصال باید ثابت بمانند.

این تفکیک مهم است. IP، MAC و پورت ورودی ویژگی شبکه‌اند و جای گذرواژه، OTP یا عامل بایومتریک را نمی‌گیرند.

چهار سیاست احراز هویت در آزمایش وجود دارد:

| سیاست | عامل‌های لازم |
|---|---|
| Password | گذرواژه |
| Password + OTP | گذرواژه و OTP نرم‌افزاری |
| Password + Biometric | گذرواژه و نمونه بایومتریک نرم‌افزاری شبیه‌سازی‌شده |
| Full MFA | گذرواژه، OTP نرم‌افزاری و نمونه بایومتریک شبیه‌سازی‌شده |

هر سیاست با چهار binding شامل IP، ‏IP+MAC، ‏IP+port و ‏IP+MAC+port ترکیب می‌شود. سناریوهای شبکه عبارت‌اند از دسترسی غیرمجاز، جعل IP، جعل هم‌زمان IP و MAC، ‏ARP/MITM، سیل UDP تک‌مبدأ و سیل UDP سه‌مبدأ. هر سناریو در سه شدت کم، متوسط و زیاد و روی سه توپولوژی Mininet اجرا می‌شود.

با پنج تکرار، حجم کامل مطالعه چنین است:

| بخش مطالعه | تعداد مشاهده |
|---|---:|
| راستی‌آزمای احراز هویت | ۸۴۰ |
| ماتریس مستقل شبکه | ۴٬۳۲۰ |
| ماتریس زنجیره‌ای انتها‌به‌انتها | ۳۴٬۵۶۰ |
| مجموع | ۳۹٬۷۲۰ |

ماتریس مستقل امکان مقایسه سیاست، binding، شدت و توپولوژی را بدون آمیختن نتیجه ورود با نتیجه شبکه فراهم می‌کند. ماتریس زنجیره‌ای مسیر کامل حمله به احراز هویت، تصمیم ورود، مجوز SDN و نتیجه شبکه را دنبال می‌کند.

## مدل احراز هویت

گذرواژه‌ها با scrypt، نمک تصادفی و هش مستقل نگهداری می‌شوند. OTP نرم‌افزاری تصادفی، کوتاه‌عمر و یک‌بارمصرف است و به کاربر و همان تلاش ورود متصل می‌شود. مقدار OTP به‌صورت HMAC همراه pepper ذخیره می‌شود.

بخش بایومتریک مطابق دامنه پژوهش، شبیه‌سازی نرم‌افزاری است. این مدل از template رمز‌شده ۶۴بعدی، probeهای genuine و impostor، امتیاز شباهت و آستانه تصمیم استفاده می‌کند و گزارش آن ROC، ‏FAR، ‏FRR و EER را محاسبه می‌کند. این قسمت ارزیابی حسگر فیزیکی یا تشخیص زنده‌بودن نیست و امکان replay در نبود liveness به‌صراحت به‌عنوان محدودیت باقی می‌ماند.

## محیط اجرا

محیط مرجع Linux و Python 3.9 است و به PostgreSQL همراه `pgcrypto`، ‏Mininet، ‏Open vSwitch و Ryu 4.34 نیاز دارد. بررسی اولیه همچنین وجود `curl`، ‏`ip`، ‏`ping`، ‏`psql` و `tcpdump` را کنترل می‌کند.

محیط پایتون از ریشه مخزن ساخته می‌شود:

```bash
python3.9 -m venv --system-site-packages venv
./venv/bin/pip install --upgrade pip
./venv/bin/pip install setuptools==67.8.0 wheel==0.45.1 pbr==5.11.1
./venv/bin/pip install --no-build-isolation -r requirements.txt
```

فایل تنظیمات محلی ساخته و دسترسی آن محدود می‌شود:

```bash
cp .env.example .env
chmod 600 .env
```

اطلاعات پایگاه داده و هر چهار secret مستقل در `.env` لازم‌اند. هر secret را می‌توان جداگانه با فرمان زیر ساخت:

```bash
./venv/bin/python -c "import secrets; print(secrets.token_urlsafe(48))"
```

پس از آن schema آماده می‌شود و دست‌کم یک حساب فعال و غیرآزمایشی با عامل‌های مورد نیاز Full MFA ساخته می‌شود:

```bash
./venv/bin/python database/auto_migrator.py
./venv/bin/python admin/user_management.py
./venv/bin/python tools/preflight_check.py
```

اجراکننده در صورت نیاز cohort جداگانه‌ای شامل ۵۰۰ کاربر مصنوعی می‌سازد. حساب‌های عادی وارد این cohort نمی‌شوند و هنگام جایگزینی cohort نیز حذف نخواهند شد.

## اجرای مطالعه

برای هر سه توپولوژی باید seed و تعداد تکرار یکسان باشد:

```bash
sudo -E ./venv/bin/python run_thesis_v2.py \
  --topology star-small --seed 20260822 --repetitions 5 \
  --phase complete
```

```bash
sudo -E ./venv/bin/python run_thesis_v2.py \
  --topology tree-medium --seed 20260822 --repetitions 5 \
  --phase complete
```

```bash
sudo -E ./venv/bin/python run_thesis_v2.py \
  --topology partial-mesh-medium --seed 20260822 --repetitions 5 \
  --phase complete
```

حالت `complete` بخش مستقل و بخش زنجیره‌ای را اجرا یا ادامه می‌دهد. حالت `factorial` فقط ماتریس مستقل و حالت `chained` فقط ماتریس زنجیره‌ای را اجرا می‌کند. برای دیدن طرح قطعی بدون تغییر پایگاه داده و بدون اجرای Mininet می‌توان از dry run استفاده کرد:

```bash
./venv/bin/python run_thesis_v2.py \
  --topology star-small --seed 20260822 --repetitions 5 \
  --phase complete --dry-run
```

شناسه taskهای تکمیل‌شده در PostgreSQL نگهداری می‌شود. تکرار فرمان پس از توقف، taskهای معتبر را رد می‌کند و موارد ناتمام یا دارای خطای فنی را دوباره انجام می‌دهد. جزئیات بیشتر در [راهنمای اجرا](docs/USAGE.fa.md) آمده است.

## گزارش‌ها

هنگام اجرای مطالعه، گزارش ناقص برای بررسی روند کار به‌روزرسانی می‌شود. گزارش strict نهایی فقط وقتی ساخته می‌شود که تمام مشاهده‌های برنامه‌ریزی‌شده معتبر باشند و هیچ خطای فنی باقی نمانده باشد:

```bash
./venv/bin/python analysis/article_report_v2.py --study-id STUDY_UUID
```

برای ساخت گزارش تشخیصی ناقص:

```bash
./venv/bin/python analysis/article_report_v2.py \
  --study-id STUDY_UUID --partial
```

پوشه گزارش شامل PDF فارسی و انگلیسی، داشبورد HTML دوزبانه، CSVهای خام، خلاصه آماری JSON و نمودارهای PNG، ‏SVG و PDF است. مقایسه سیاست‌ها و bindingها، منحنی شدت، دسترس‌پذیری و بازیابی، ECDF تأخیر، ROC/FAR/FRR بایومتریک و زنجیره انتها‌به‌انتها در خروجی‌ها قرار دارند.

فقط مشاهده‌های معتبر فنی وارد مخرج نرخ‌های امنیتی می‌شوند. خطای انتقال، بازیابی ناقص یا شکست کنترل پایه، `technical_error` است و حمله مسدودشده محسوب نمی‌شود.

## ساختار مخزن

| مسیر | محتوا |
|---|---|
| `config/` | پروتکل، توپولوژی‌ها و برنامه Ryu |
| `controller/` | دروازه احراز هویت، مجوزدهی و اجرای campaign |
| `attacks/` | سناریوهای ایزوله Mininet و اندازه‌گیری‌ها |
| `experiments/` | طرح مستقل، مطالعه احراز هویت و مطالعه زنجیره‌ای |
| `security/` و `otp/` | گذرواژه، OTP و بایومتریک شبیه‌سازی‌شده |
| `database/` | schema، مهاجرت و ثبت رویدادها |
| `analysis/` | آمار، نمودار، PDF و داشبورد HTML |
| `tests/` | آزمون‌های واحد، پروتکل، امنیت و گزارش |

## بازتولیدپذیری و دامنه نتیجه

شناسه‌های مطالعه، campaign، ‏task و chain برای پروتکل، seed و تعداد تکرار ثابت، قطعی‌اند. ترتیب سیاست‌ها در بلوک‌های مقایسه تصادفی می‌شود، اما ورودی نمونه‌گیری‌شده درون هر بلوک ثابت می‌ماند. manifestها و شواهد صادرشده نیز اطلاعات کنترل تمامیت دارند.

نتایج به همین پیاده‌سازی، مدل تهدید تعریف‌شده، توپولوژی‌های انتخاب‌شده و مدل‌های نرم‌افزاری عامل‌ها مربوط‌اند. این آزمایش به‌تنهایی آمادگی محیط عملیاتی، دقت بیومتریک فیزیکی یا مقابله با همه حملات دنیای واقعی را اثبات نمی‌کند. همچنین MFA در این پروژه راه‌حل ذاتی حمله حجمی DoS در نظر گرفته نشده است.
